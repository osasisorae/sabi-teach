# Gemma 4 Good Hackathon Overview

Captured on April 26, 2026.

## Competition

- Title: Gemma 4 Good Hackathon
- Sponsor: Google LLC
- Platform: Kaggle
- Competition page: `https://www.kaggle.com/competitions/gemma-4-good-hackathon`
- Theme: build a real-world solution using Gemma 4 models

## Core Mission

Build a solution that addresses a real-world challenge using Gemma 4 models. The project can be:

- an application with large-scale impact, or
- a specialized model that can scale innovation in a focused domain

The competition framing emphasizes:

- local frontier intelligence
- native function calling
- multimodal understanding
- practical deployment in constrained environments

The prompt specifically highlights environments such as:

- classrooms with unreliable internet
- medical sites far from data centers
- privacy-sensitive communities

## Priority Impact Areas

- Health & Sciences: tools that accelerate discovery or democratize knowledge
- Global Resilience: offline, edge-based, disaster-response, climate, or infrastructure tools
- Future of Education: adaptive multi-tool agents for learners and educators
- Digital Equity & Inclusivity: linguistic access, intuitive interfaces, and AI skills access
- Safety & Trust: transparency, reliability, and explainability

## Technical Direction Encouraged By The Hackathon

The overview explicitly encourages solutions that use Gemma 4 through:

- post-training
- domain adaptation
- agentic retrieval
- grounded output design
- edge deployment with E2B and E4B models
- larger-weight deployment with 26B and 31B models for more complex tasks

Additional guidance:

- If training a model, publish weights and benchmarks.
- If building an app, explain the architecture and show a functional demo with real-world utility.

## Submission Story Requirement

The submission is not only technical. It must present a strong story:

- clearly define the real-world problem
- show how the Gemma 4 solution addresses it
- deliver a "wow" factor
- communicate the vision through the writeup and especially the video

## Required Submission Components

A valid submission must include:

- Kaggle writeup
- attached public video
- attached public code repository
- attached live demo
- media gallery

Important constraints:

- Each team can submit only one writeup.
- That writeup can be unsubmitted, edited, and resubmitted.
- Draft or unsubmitted writeups at the deadline will not be judged.
- A cover image is required in the media gallery.

## Kaggle Writeup Requirements

- Must include a title, subtitle, and detailed analysis
- Must select a track
- Must not exceed 1,500 words
- Should explain:
  - app architecture
  - how Gemma 4 was used specifically
  - challenges overcome
  - why the technical choices were correct

Primary purpose of the writeup:

- verify that the demo is backed by real engineering

## Video Requirements

- Must be attached through the media gallery
- Must be 3 minutes or less
- Must be published on YouTube
- Must be directly viewable by judges without login

Video emphasis:

- tell a story
- demonstrate real-world impact
- show the product in action
- be dynamic, engaging, and high-quality

## Code Repository Requirements

- Must be public
- Can be GitHub or a Kaggle notebook
- Must be well-documented
- Must clearly show the implementation of Gemma 4
- Must not require login or a paywall

Purpose:

- serves as the source of truth
- used to validate authenticity and technical depth

## Live Demo Requirements

- Must be publicly accessible
- Can be a URL or attached files
- Must not require login or paywall
